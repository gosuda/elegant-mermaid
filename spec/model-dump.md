# Model-stage dump

This file fixes the dump that `emd layout --stage model` prints, which the Lean reference reads as its input.

## Shape and bytes

- model-dump-01: The model-stage dump MUST use the JSON shape and byte rules of the canonical layout dump of `spec/layout-dump.md`, with `"stage":"model"`. [just lean-parity]
- model-dump-02: The dump MUST NOT hold `canvas`. [just lean-parity]
- model-dump-03: A box MUST NOT hold `x`, `y`, `w`, or `h`. [just lean-parity]
    A group box MUST carry `direction` after `exclusive`: `TB`, `BT`, `LR`, or `RL` for its own direction statement, or the empty string when no statement exists. A node box MUST carry this key only under model-dump-24. This key MUST exist only in the model stage; the layout-stage box schema MUST remain unchanged.
    A group box MUST have `exclusive` `false`, because a group frame holds its member boxes. A model whose group box has `exclusive` `true` is not well formed.
    A model-stage box MUST carry `shape` after `direction`, when that key exists, or after `exclusive` otherwise, only for a non-empty shape other than `rect`. An absent or empty shape MUST denote `rect`. The internal shape `squareRect` MUST use the default `rect` representation. A layout-stage box MUST NOT carry `shape`.
    A model-stage box MUST carry `"icon":true` exactly when its resolved flowchart icon name is nonempty, after `shape` when that key exists, or otherwise after the last preceding box key, and before `text`. The writer MUST omit `icon` when false. A reader MUST read an absent `icon` as false, preserve either Boolean value when present, and reject a present value of any other type. Shape alone MUST NOT imply icon presence. A layout-stage box MUST NOT carry `icon`.
- model-dump-04: A route MUST NOT hold `points`. [just lean-parity]
- model-dump-05: A label MUST NOT hold `x`, `y`, `w`, or `h`. [just lean-parity]
- model-dump-06: The model stage MUST write each label's unwrapped text in `text` and an empty array in `lines`, which MUST be written as `"lines":[]`. [just lean-parity]
- model-dump-07: Measurement MUST fill `lines` from the profile and `max_width`. [just lean-parity]
- model-dump-08: The `options` object MUST hold the resolved options, `direction` included, and every honoured config key that affects layout, in the key order of `spec/layout-dump.md`. [just lean-parity]
- model-dump-09: `emd layout --stage model [--profile P]` MUST print the dump before measurement and layout: the kind, the boxes (nodes and groups), the routes (edges), and the labels with their unwrapped text, and no coordinates. [just go-check]

## Readers

- model-dump-10: `geomcheck layout` MUST read the model-stage dump from stdin and print the canonical layout dump. [just lean-parity]
- model-dump-11: `geomcheck text --charset unicode|ascii` MUST read the model-stage dump from stdin and print the text rendering, under the cell profile and with colour off. [just lean-parity]
- model-dump-12: `proofs/Elegant/Dump.lean` MUST hold the reader of the model-stage dump and the `toDump` writer of the layout dump. [just proofs]

## Golden example

- model-dump-13: The model-stage dump of the input `flowchart` header followed by the line `A -->|yes| B` MUST be these bytes, with one LF at the end of the last line. [just lean-parity]

    ```
    {"version":1,"stage":"model","kind":"flowchart","profile":"vector","options":{"profile":"vector","thoroughness":3,"max_width":0,"direction":"TB","limits":{"max_nodes":2000,"max_edges":5000,"max_text_bytes":1048576}},
    "boxes":[{"id":"A","role":"node","parent":"","exclusive":true},
    {"id":"B","role":"node","parent":"","exclusive":true}],
    "routes":[{"id":"e0","from":"A","to":"B","orthogonal":true}],
    "labels":[{"id":"e0.label","owner":"e0","text":"yes","lines":[]}]}
    ```

## Parity binding

- model-dump-14: The two comparisons of this dump against `geomcheck layout` and `geomcheck text` MUST be the ones that `spec/lean-reference.md` fixes. [just lean-parity]
- model-dump-15: `emd layout --stage model` MUST run neither measurement nor layout, so it MUST print the dump before both stages. [just go-check]
- model-dump-16: The model-stage dump MUST be one of the inputs that `just parity` compares between the Go and Rust binaries. [just parity]
    Generated route IDs MUST be `e0`, `e1`, and successive decimal numbers in route declaration order, skipping every model box ID and previously allocated route ID. Source box IDs and explicit source edge identifiers MUST remain unchanged. Algorithms MUST retain declaration indices separately and MUST NOT derive them from numeric ID suffixes. Generated route labels MUST use the allocated route ID as owner. A reader MUST reject a supplied label owner that ambiguously names both a box and a route.
- model-dump-17: A box label MUST be a label record with the id `<boxId>.label` and the box as `owner`, written exactly when the label text of the box differs from its id, an empty label included, except for a box whose frontend carries that text in the `text` key of the box instead (model-dump-21); a box with neither record nor `text` key has its id as its label text; the box label records MUST come first, in box order, then the route label records in route order. [just lean-parity]
    This rule MUST include group titles. The synthetic graph item that reserves title space MUST NOT create another label record. A group-owned title record MUST retain its placed rectangle and lines in the layout-stage dump and MUST correspond to the scene `Text` in that group's drawing group.
- model-dump-18: A label record owned by an exclusive box MUST exist only in the model stage, where it carries the box text for measurement; layout MUST draw that text inside the box as scene `Text` primitives and MUST NOT write the record to the `labels` array of the layout-stage dump, so clause `label-clearance` of `spec/layout-dump.md` applies only to labels that layout places as separate objects. [just lean-parity]
- model-dump-19: A model-stage route record MUST carry the keys `marker_start`, `marker_end`, and `stroke` after `orthogonal`, in that order, each written only when its value differs from its default: no marker at the source end, the marker `point` at the target end, and the stroke `normal`; a target end with no marker MUST be written as `"marker_end":"none"`; the layout-stage dump MUST NOT carry these keys. The closed stroke names MUST be `normal`, `thick`, `dotted`, `dashed`, and `invisible`. A solid class relation MUST use the default `normal`. [just lean-parity]
    The optional `from_side` and `to_side` keys MUST follow these style keys, in that order. Their values MUST be `T`, `B`, `L`, or `R` for the top, bottom, left, or right rectangle face. An absent key MUST denote the ordinary layered port. Readers MUST reject any other value or type. A layout-stage route MUST NOT carry these keys.
- model-dump-20: Every edge MUST have minimum length 1 unless its route record carries `min_length` (model-dump-22); the count of stroke bytes of a link MUST NOT change the rank of a node, and a labelled edge takes minimum length 2 when label nodes arrive. [just lean-parity]
- model-dump-21: A model-stage box MUST carry the key `text` exactly when no label record names the box as `owner`, the box text is not empty, and the box text differs from the box id. [just parity]
    The key MUST follow `icon` when `icon` exists, otherwise `shape` when `shape` exists, and otherwise the last key before it (`direction` or `exclusive`). The value MUST be one JSON string: the exact text that layout measures for the box, which the label rule of model-dump-17 would otherwise take from the id. The string MUST NOT be wrapped, and the writer MUST NOT rewrite its line breaks: they stay as the kind makes them, which is LF for the state descriptions and notes, and the `erBox` form below for ER. A layout-stage box MUST NOT carry `text`, and a box that has a label record MUST NOT carry it, so every label-bearing box keeps its bytes.
    A box with shape `erBox` writes the encoded entity table `H<br/><br/>R1<br/>R2` and so on: `H` is the entity display name, and each `Ri` is one attribute row of exactly four fields, in this order: type, name, the key list joined by `,`, and comment. The fields of a row are joined by `|`. An entity with no attribute rows ends with `<br/><br/>`. Every name and field MUST be encoded by these replacements, applied in one left-to-right pass: `\` as `\\`; `|` as `\p`; `<` as `\l`; TAB as `\t`; LF as `\n`; and each of `<br>`, `<br/>`, and `<br />` (ASCII letters in either case) as `\n`. A reader MUST split `H` from the rows at the first `<br/><br/>`, split the rows at `<br/>`, split each row at `|`, and then decode each field by the inverse replacements: `\n` as LF, `\t` as TAB, `\p` as `|`, `\l` as `<`, any other `\` pair as its second character, and a lone final `\` as itself. A row is one measured line per LF of its decoded fields, and its height is that of its tallest field.
    A group box that has no label record writes its title with each CR, LF, and CRLF replaced by `<br/>`. This applies to the ER groups, whose titles do not become label records.
- model-dump-22: A model-stage route record MUST carry the key `min_length` exactly when its minimum rank length is greater than the default of that route, and MUST omit it otherwise. [just parity]
    The minimum rank length is the integer, at least 1, that the layered family reads from the edge options of the route. The default is 1 for a route that no label record names as `owner`, and 2 for a route that some label record names as `owner`, because layout raises every labelled edge to at least 2 (model-dump-20). The kind sources of the minimum are the number of dashes of a solid link operator of `usecase`, and the `length` of an `agentflow` edge. The `flowchart` kind keeps the default for every edge: its extra-dash length is not an edge option. A reader MUST take the layout length as the larger of `min_length` (1 when absent) and the default. The value MUST be an integer of at least 2, written in minimal decimal. The key MUST follow `to_side` when that key exists, and otherwise the last key before it. A layout-stage route MUST NOT carry `min_length`.
- model-dump-23: The writer MUST write the target marker of a route by this rule: a frontend marker `point` is omitted; every other named marker is written; and an absent or empty frontend marker, which layout draws as no marker, MUST be written as `"marker_end":"none"`. A model-stage route record MUST NOT carry an empty marker name. A reader MUST read an absent `marker_end` as `point` and `"marker_end":"none"` as no marker. The source end needs no such rule: an absent, empty, or `none` source marker all mean no marker, so the writer omits `marker_start` for each of them. [just parity]
- model-dump-24: A node box MUST carry `direction` after `exclusive` exactly when its frontend direction token is not empty, and the writer MUST write that token unchanged. [just parity]
    The group rule of model-dump-03 does not change: a group box always carries the key, with the empty string when the frontend token is empty. The writer MUST NOT validate the token. Its meaning belongs to the kind: for the kind `sequence`, `w` means that the text of the box wraps and `n` means that it does not wrap, and every other token of that kind means the shared wrap option; for the kind `state`, a note node carries `left` or `right` for its side of the state it annotates, and a group box carries the direction token of its scope. A reader MUST accept `TB`, `BT`, `LR`, and `RL` on a group box of every kind, MUST also accept `w` and `n` on a group box of the kind `sequence`, and MUST accept `left` and `right` on a node box of the kind `state`. A layout-stage box MUST NOT carry the key. The keys `shape`, `icon`, and `text` follow `direction` when they exist (model-dump-03 and model-dump-21).
- model-dump-25: A model-stage dump MUST carry the member `regions` after `labels` exactly when the frontend has at least one region set, and MUST omit it otherwise. [just parity]
    The value MUST be one JSON array with one inner array of integers for each region set, in the order of the frontend. The first integer of an inner array is the parent of the region set. The integers after it are its regions, unchanged and in their order. An integer MUST be written in minimal decimal, and an absent index MUST be written as `-1`. The writer MUST NOT re-index, sort, or interpret an integer. The kind defines the meaning of the integers. For the kind `state`, the integers are indices into the group boxes in box order. For the kind `sequence`, the parent is the position of the event in the event order, and the first region is the event tag of the Go function `decodeSequenceSteps`. The member MUST start on a new line, and each inner array after the first MUST start on a new line, as the other top-level arrays do. A layout-stage dump MUST NOT carry `regions`. A reader MUST read an absent `regions` as no region set.
